## KEY ARCHITECTURE DECISIONS

### 1. Five-Tier Language Classification

**Why?** Balances implementation speed with feature complexity

```
TIER 1 (Quick Wins):
  Go, Rust, TypeScript
  Carryover: 65-75% from Phase B
  Complexity: MEDIUM
  Days: 11 per language
  Features: Concurrency, type system, DSL basics

TIER 2 (Advanced):
  Kotlin, Scala, OCaml
  Carryover: 55-80% from Phase B
  Complexity: HARD
  Days: 13-15 per language
  Features: Extensions, implicits, modules

TIER 3 (Frontier):
  Haskell, F#, Lisp
  Carryover: 40-65% from Phase B
  Complexity: VERY HARD
  Days: 13-15 per language
  Features: Kinds, computation expressions, macros
```

### 2. 34-Test Standard Per Language

**Why?** Proven from Phase B success (10 tests per Phase A+B)

```
Scaling to Phase C (34 tests):
├─ Category A: Parsing (8) - Basic feature recognition
├─ Category B: AST Validation (8) - Semantic correctness
├─ Category C: Code Generation (6) - Output quality
├─ Category D: Semantic Analysis (6) - Issue detection
├─ Category E: Integration Tests (4) - End-to-end pipeline
└─ Category F: Performance Tests (2) - Benchmarking

Total: 34 = 8+8+6+6+4+2
```

### 3. Forensic Debug Framework

**Why?** Learned from Gleam parser hang (Phase B)

```
4-Layer Debug Architecture:
├─ Layer 1: Prevention (HangDetector, iteration bounds)
├─ Layer 2: Observation (Tracing tools for each feature)
├─ Layer 3: Measurement (Performance profiling)
└─ Layer 4: Isolation (Safe sandbox execution)

Prevents hangs + detects regressions + enables rapid debugging
```

### 4. Parallel Workstreams

**Why?** 5-week sequential timeline → 10-12 days with parallelization

```
Dependency Graph:
Week 1: Framework → Tier 1 (parallel)
Week 2: Tier 1 ✓ → Tier 2 + Validators (overlap)
Week 3: Tier 2 ✓ → Tier 3 + Forensics (overlap)
Week 4: Tier 3 ✓ → Original 4 extensions + harness
Week 5: All complete → Optimization + documentation

Critical path: 27 days → 10-12 days with 3-5 workstreams
```
