# LUASCRIPT Denali Compatibility Matrix

Status: active current-host release-candidate compatibility contract  
Last updated: 2026-07-29  
Package state: `luascript@0.1.0-beta.0`; no release action has occurred

This document defines what LUASCRIPT compatibility evidence protects for the
Denali `1.0` release candidate. The machine-readable authority is
`artifacts/conformance/denali-compatibility-matrix-report.json`, generated by
`npm run test:compatibility-matrix`. This page explains the boundary; it never
overrides a report whose status is `OPEN` or `FAIL`.

## Compatibility Verdict Model

The matrix has three states:

- `PASS`: the live file, command, report, and hash relationships checked on the
  current host agree.
- `OPEN`: an evidence artifact is absent or stale, even if its previous result
  was green. Regenerate the owning evidence before release.
- `FAIL`: live package, manifest, source, runtime, schema, or required-command
  truth contradicts the contract.

Any `OPEN` or `FAIL` item blocks the Denali RC preflight. A passing current-host
matrix is not cross-platform certification, broad language support, source
identity, semantic equivalence, or permission to release.

## Setup Notes And Hidden Pairings

- LUASCRIPT compilation uses Python and emitted `.ls` execution uses Lua.
- Java needs both `javac` and `java`.
- Kotlin needs `kotlinc` and Java.
- Elm needs `elm` and Node.
- C and C++ target matrices can require both compiler families.
- C# needs an SDK capable of the harness target, not merely a visible `dotnet`
  executable.
- Gleam may additionally depend on Erlang and a usable package cache.
- Emitted targets add Node, Python, Lua, .NET, C, or C++ requirements even when
  the source language uses another native tool.

Missing tools are failures, never silent skips. Alternative command candidates
and the existing `.tools` fallback are recorded in the report so another
operator can reproduce how the selected command was found.

remain semantically equal except for their top-level `$id`.

## Cross-Platform Boundary

This local RC matrix proves one Windows x64 environment plus the separately
executed Node `14.17.1` installed-consumer floor smoke. Linux, macOS, other
architectures, alternative compilers, and other runtime versions remain
unclaimed until the same report is generated there or CI produces equivalent
receipts.

That exclusion is acceptable only because Denali makes a scoped current-host
RC claim. It is not acceptable wording for a future broad cross-platform
support claim. Cross-platform promotion requires:

1. the same package tarball identity or a source-state receipt;
2. all required runtime/tool versions;
3. schema-v2 language reports with live hashes;
4. a zero-`OPEN`, zero-`FAIL` compatibility report;
5. preservation of platform-specific failures rather than exclusions added
   merely to make CI green.

## Authoritative RC Reproduction

From the repository root:

```bash
npm run denali:rc:preflight
```

That 26-step command regenerates every required producer in dependency order,
runs this compatibility matrix only after its bound inputs, and runs the
deterministic evidence generator with `--require-ready` last.

For a focused compatibility refresh during development, after all other bound
reports and docs are already current, use:

```bash
npm run language:implemented:bidirectional
npm run test:package-contract
npm run test:compatibility-matrix
```

The focused sequence is not the complete RC gate. The first command regenerates
language behavior and provenance, the second creates and tests the actual
package tarball, and the third binds those artifacts to live source, manifests,
schemas, docs, dependencies, and current runtime probes.

Any change to package metadata, package examples, language manifests/sources,
compiler implementations, support docs, release schemas/contracts, or bound
manifests requires regeneration before the matrix; use the authoritative
preflight for a release-candidate verdict.

## Release Boundary

The compatibility matrix performs no dependency installation, version bump,
commit, tag, publish, GitHub release, package API mutation, language promotion,
or external-state change. A passing matrix is necessary evidence for the
Denali RC; it is not release authorization.
